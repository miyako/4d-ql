# fourdql CLI reference

`fourdql` inspects 4D files and produces a readable text report, a typed JSON
analysis, or a self-contained HTML preview. It uses the same analyzers and
presenters as the Finder Quick Look extension, without requiring the hosting
app, a running database, 4D, or SpreadJS.

The HTML previews are static documents, not a way to run 4D applications.
Database records are not exported or decrypted, methods and formulas are not
executed, and the original files are not edited.

## Installation

### Download for macOS

Download a CLI asset from [Releases](https://github.com/miyako/4d-ql/releases):

| Asset | Contents and notarization |
|---|---|
| `fourdql-X.Y.Z-macos-universal.dmg` | Developer ID-signed executable for Apple Silicon and Intel, usage information and licenses; the notarized DMG carries a stapled ticket |
| `fourdql-X.Y.Z-macos-universal.zip` | The same signed executable and documentation; notarized, but ZIPs and standalone executables cannot carry a stapled ticket |

The macOS downloads require macOS 12 or later. No Swift installation or
Quick Look registration is necessary. The DMG is the distribution option with
a stapled notarization ticket; the ZIP may require internet access for
Gatekeeper verification on first use. The ticket is attached to the DMG,
not to the executable after copying it elsewhere.

Mount the DMG or extract the ZIP, then run `./fourdql --help` from the directory
containing the executable. Do not double-click it expecting a graphical app.
The images below show HTML generated by the CLI and opened in a browser.

### Install on your PATH

For example, after downloading the DMG, install in your own account without
administrator access. Set `VERSION` to the version you downloaded:

```sh
VERSION=0.13.0
hdiutil attach "./fourdql-${VERSION}-macos-universal.dmg"
mkdir -p "$HOME/.local/bin"
install -m 755 "/Volumes/fourdql ${VERSION}/fourdql" "$HOME/.local/bin/fourdql"
hdiutil detach "/Volumes/fourdql ${VERSION}"
export PATH="$HOME/.local/bin:$PATH"
fourdql --help
```

For the ZIP, the extracted folder is named
`fourdql-X.Y.Z-macos-universal`:

```sh
VERSION=0.13.0
ditto -x -k "./fourdql-${VERSION}-macos-universal.zip" .
mkdir -p "$HOME/.local/bin"
install -m 755 "./fourdql-${VERSION}-macos-universal/fourdql" "$HOME/.local/bin/fourdql"
export PATH="$HOME/.local/bin:$PATH"
fourdql --help
```

Add the `export PATH=...` line to your shell's startup file if you want it to
persist in new terminals. To update, replace the executable with one from the
new release. To uninstall, remove the executable you installed; the CLI does
not register a background service or a Quick Look extension.

You can inspect its signature with the macOS system tool:

```sh
codesign --verify --strict --all-architectures "$HOME/.local/bin/fourdql"
codesign -dv --verbose=4 "$HOME/.local/bin/fourdql"
```

Keep the included project and Selawik font licenses when redistributing the
download. The CLI's embedded font is used for Windows-style form previews.

### Windows and Linux downloads

The hosted workflows also produce these standalone x86-64 CLI packages:

| Asset | Platform and contents |
|---|---|
| `fourdql-X.Y.Z-windows-x86_64.zip` | Windows executable, required runtime DLLs, usage information and licenses; unsigned |
| `fourdql-X.Y.Z-linux-x86_64.tar.gz` | Ubuntu 24.04-compatible Linux executable, launcher, runtime libraries, usage information and licenses; experimental rendering |

These are CLI distributions, not Windows Explorer or Linux desktop preview
extensions. They do not require 4D or a Swift development installation.
Windows ARM64 and Linux ARM64 native packages are not built. Windows validation
uses the GitHub-hosted `windows-latest` runner; Linux validation uses
`ubuntu-24.04`. The Linux package is not a universal Linux binary: it requires
an x86-64, glibc-based environment compatible with Ubuntu 24.04, not Alpine/musl.
Its system baseline includes glibc 2.39 or later, `libgcc-s1`, `libstdc++6`,
`/bin/sh` and coreutils; those OS components are not bundled.

Extract the **entire folder** and keep its executable, libraries and licenses
together. On Windows, use PowerShell in the download directory, replacing
`X.Y.Z` with the downloaded version:

```powershell
$Version = "X.Y.Z"
Expand-Archive ".\fourdql-$Version-windows-x86_64.zip" -DestinationPath .
& ".\fourdql-$Version-windows-x86_64\fourdql.exe" --help
& ".\fourdql-$Version-windows-x86_64\fourdql.exe" --html "C:\Documents\Workbook.4vp" > preview.html
```

Add the extracted folder to your user `PATH` if desired; do not copy just
`fourdql.exe` into another directory. There is no Authenticode signature, so
Windows may display a downloaded-application warning.

On compatible Linux:

```sh
VERSION=X.Y.Z
mkdir -p "$HOME/.local/opt"
tar -xzf "./fourdql-${VERSION}-linux-x86_64.tar.gz" -C "$HOME/.local/opt"
"$HOME/.local/opt/fourdql-${VERSION}-linux-x86_64/fourdql" --help
export PATH="$HOME/.local/opt/fourdql-${VERSION}-linux-x86_64:$PATH"
fourdql --html "/path/to/Workbook.4vp" > preview.html
```

Run the top-level `fourdql` launcher, not `libexec/fourdql` directly. The
launcher locates its own runtime libraries without modifying your shell's
environment. To update or uninstall either platform, replace or remove the
whole extracted directory and adjust `PATH`.

**Linux rendering limitations:** parsing and text/JSON/HTML output are
available, but font measurements use approximate fallback metrics and raster
picture conversion is unavailable. Form/diagram geometry and artwork can
differ from macOS and Windows. Successful CLI smoke tests do not establish
pixel-identical rendering; the gallery below was captured on macOS.

Packages appear on releases made from tags containing the portable workflows.
Older releases, including the original v0.13.0 assets, are not automatically
backfilled. Before a tagged release, download the `fourdql-0.0.0-ci.*-*`
artifacts from a successful [CI run](https://github.com/miyako/4d-ql/actions/workflows/ci.yml).
GitHub wraps each Actions artifact in an additional ZIP; extract that first
to obtain the actual distribution archive.

## Command syntax

```text
fourdql [--json | --html] [--thorough] <file>...
```

| Option | Effect |
|---|---|
| No output option | Print a human-readable report to standard output, including details and source text where applicable |
| `--json` | Print the analyzer's typed model as pretty-printed JSON; this is analysis data, not necessarily the file's original JSON |
| `--html` | Print a complete HTML document suitable for saving and opening in a browser |
| `--thorough` | Remove the optional analysis time budget and record-scan cap, and enable structure-resource counting; format-specific safety and output limits remain |
| `-h`, `--help` | Print usage and exit |
| `--content-types` | Print the registered 4D Uniform Type Identifiers and exit; primarily used by the app build |

Use one output option at a time. If both `--json` and `--html` are given, the
last one wins. Options apply to the entire invocation, not to individual files.

Input is by file path, not standard input. Quote paths containing spaces.
There is no `--output`, `--version`, image/PDF export, or `--` option separator;
use shell redirection for output and prefix a special-looking filename with
`./` when needed. The CLI selects its analyzer by the case-insensitive filename
extension. Renaming arbitrary XML, JSON or Excel files does not convert them
into supported 4D documents.

## Examples

### Inspect files in the terminal

```sh
fourdql "/path/to/Database.4DD"
fourdql "/path/to/Structure.4DB" "/path/to/Project/Sources/catalog.4DCatalog"
fourdql "/path/to/Project/Sources/Methods/Calculate total.4dm"
```

Text mode prints a heading for each file. Graphical previews are summarized
as text rather than drawn in the terminal. Collapsible report details are
printed too, so reports containing original source can be long.

### Save structured analysis

```sh
fourdql --json "/path/to/Workbook.4vp" > workbook.analysis.json
fourdql --json --thorough "/path/to/Structure.4DB" > structure.analysis.json
```

The JSON contains a `kind` discriminator, such as `4d.viewpro`, and the
format-specific parsed model. Warnings, omitted data and partial-analysis
status are part of the relevant model; inspect them rather than assuming
every count is complete.

### Open an HTML preview

```sh
fourdql --html "/path/to/Workbook.4vp" > workbook.html
open workbook.html
```

The generated page contains its styles and supported embedded artwork.
It does not require the Quick Look app or a local web server. Script-free
selectors and zoom presets work where supplied by the preview. Native
Quick Look pinch zoom and drag controls belong to the app's viewer, not to
the standalone HTML page.

### Process multiple files safely

Text mode accepts several paths:

```sh
fourdql ./*.4vp
```

For JSON and HTML, use one output file per invocation. Several inputs produce
several complete JSON or HTML documents concatenated on stdout: JSON output
is neither an array nor newline-delimited JSON.

For a batch that stops if analysis fails, use JSON mode:

```sh
for file in ./*.4vp; do
    [ -f "$file" ] || continue
    fourdql --json "$file" > "${file%.4vp}.analysis.json" || exit 1
done
```

## Supported file types

There are 16 document families. `.data` is an additional extension for the
same data-file analyzer as `.4DD`.

| File extension | Capabilities | Preview |
|---|---|---|
| `.4DD`, `.data` | Table/record statistics, field types, database identity, storage, journal and encryption metadata | [Data files](#data-files) |
| `.4DB` | Binary structure tables, fields, relations and database identity | [Binary structures](#binary-structures) |
| `.4DCatalog` | XML catalog tables, fields, primary keys and relationship diagram | [Catalogs](#catalogs) |
| `.4DSettings` | Syntax-highlighted settings XML source | [Settings](#settings) |
| `.4DLink` | Syntax-highlighted database-shortcut XML source | [Database shortcuts](#database-shortcuts) |
| `.4DPreferences` | Syntax-highlighted preferences XML source | [Preferences](#preferences) |
| `.4si` | Ordered import/export fields, types and saved options | [Import/export settings](#importexport-settings) |
| `.4DProject` | Syntax-highlighted project JSON source | [Projects](#projects) |
| `.4df` | Saved query conditions, connectors, operands and destination | [Saved queries](#saved-queries) |
| `.4st` | Selected-record count, address coverage, distribution and ranges | [Saved sets](#saved-sets) |
| `.4qr` | Quick Report list/cross-table template with saved styling and totals | [Quick Reports](#quick-reports) |
| `.4lbp` | Label artwork, sheet layout and resolvable table-form references | [Labels](#labels) |
| `.4wp` | Static Write Pro page sheets with text, tables, pictures and references | [Write Pro](#write-pro-documents) |
| `.4vp` | Static View Pro worksheets with saved values, formatting and cached formula results | [View Pro](#view-pro-spreadsheets) |
| `.4dm` | Syntax-highlighted method or class source with line numbers | [Method/class source](#method-and-class-source) |
| `.4DForm` | Approximate form layout, pages, appearances and static project resources | [Forms](#forms) |

Generic `.xml`/`.json`, Excel `.xlsx`, SpreadJS `.sjs`, CSV, legacy `.4lb`
labels and arbitrary binary files are not additional input formats.
View Pro is read directly from `.4vp`, not converted by launching Excel or 4D.

## Preview gallery

These are screenshots of actual `fourdql --html` pages rendered in WebKit in
light appearance, not screenshots of a running 4D application. They show a
representative viewport, not necessarily the whole scrollable report.
The same files can also be inspected in text and JSON modes.

### Data files

`.4DD` and `.data` reports emphasize table sizes, field types and the UUID
that a matching structure must share. Encryption indicators describe saved
metadata; the CLI does not decrypt or dump records.

![CLI HTML preview of a 4D data file, showing database and table statistics](images/cli/data-file.png)

### Binary structures

`.4DB` reports show user-table definitions, fields, relations and database
identity. `--thorough` additionally attempts resource-type counting where a
resource table is present.

The screenshot uses an explicitly constructed DB4D structure sample with two
tables and eight fields, not a document exported by 4D.

![CLI HTML preview of a binary 4D structure, showing tables and field types](images/cli/structure-file.png)

### Catalogs

`.4DCatalog` previews lead with a relationship diagram. Table details include
field types, primary keys and hidden fields; other catalog metadata is folded
below the diagram.

![CLI HTML preview of a 4D catalog and its table relationship diagram](images/cli/catalog.png)

### Settings

`.4DSettings` files are shown as source, with XML syntax highlighting and
whitespace preserved. This does not apply or validate settings in a database.

![CLI HTML preview of syntax-highlighted 4D settings XML](images/cli/settings.png)

### Database shortcuts

`.4DLink` files are shown as XML source. The CLI does not follow the shortcut,
start a server connection or open the referenced database.

![CLI HTML preview of a 4D database shortcut XML document](images/cli/link.png)

### Preferences

`.4DPreferences` files are shown as XML source without changing application
preferences.

![CLI HTML preview of a 4D preferences XML document](images/cli/preferences.png)

### Import/export settings

`.4si` previews preserve saved field order and show readable field types,
table information and secondary options. The CLI does not run the import or
export operation.

![CLI HTML preview of ordered fields and options in 4D import/export settings](images/cli/import-export-settings.png)

### Projects

`.4DProject` previews display the project file's JSON source, not a combined
report of every file in the project directory.

![CLI HTML preview of a syntax-highlighted 4D project JSON file](images/cli/project.png)

### Saved queries

`.4df` previews show condition cards with table/field numbers, comparisons,
AND/OR/EXCEPT connectors, saved values and selection destinations. Queries are
not executed and field references are not resolved against a live database.

![CLI HTML preview of saved 4D query conditions and operands](images/cli/query.png)

### Saved sets

`.4st` reports show selected-record counts, coverage and contiguous ranges.
Record numbers are zero-based storage addresses, not field values or
selection positions. A time-limited scan can be explicitly partial.
See [format evidence and limits](4ST-FORMAT.md).

![CLI HTML preview of selected-record distribution and ranges in a saved 4D set](images/cli/set.png)

### Quick Reports

`.4qr` previews reconstruct saved list/cross-table report designs, including
column widths, fonts, colors, borders, sorts and totals. They are templates,
not live reports: records, formulas, print pagination and printer settings are
not evaluated. See [Quick Report format notes](QUICK-REPORT-FORMAT.md).

![CLI HTML preview of a 4D Quick Report design template](images/cli/quick-report.png)

### Labels

`.4lbp` previews render label objects, saved text, supported raster artwork and
inferred sheet layout. Referenced table forms can be resolved within their
project; missing resources produce notices. See [label format notes](LABEL-FORMAT.md).

![CLI HTML preview of a 4D label design and sheet layout](images/cli/label.png)

### Write Pro documents

`.4wp` previews reconstruct static page sheets, with saved styles, tables,
pictures, headers/footers and formula references. Text is not repaginated
after every soft wrap; pages split at explicit breaks. Supported page-number,
page-count and section-name references are computed, but application formulas
are not evaluated. See [Write Pro format notes](WRITEPRO-FORMAT.md).

![CLI HTML preview of a formatted 4D Write Pro document](images/cli/write-pro.png)

### View Pro spreadsheets

`.4vp` previews include selectable sheets, saved values and formula results,
OA dates, rich text, named styles, merged cells and saved dimensions.
Hidden sheets, rows and columns are respected. Charts, pictures, conditional
formatting and print layout are not reproduced; unsupported formatting has
explicit notices. See [View Pro format notes](VIEWPRO-FORMAT.md).

![CLI HTML preview of a 4D View Pro spreadsheet with saved cell formatting](images/cli/view-pro.png)

### Method and class source

`.4dm` previews provide source highlighting and line numbers. Highlighting is
lexical, not semantic analysis, compilation or execution. Method attributes,
tokenized commands/constants and ordinary source are recognized.

![CLI HTML preview of syntax-highlighted 4D method source with line numbers](images/cli/method.png)

### Forms

`.4DForm` previews combine page 0 with the selected numbered page, approximate
saved layout and platform appearances, and resolve supported static resources.
They do not run form methods, dynamic data sources or object events.
See the [shared form renderer contract](FORM-RENDERER.md).

![CLI HTML preview of a 4D form with page and appearance selectors](images/cli/form.png)

## Limits and project resources

Default analysis uses a 1.5-second budget for optional expensive scans and a
20,000-record scan cap where relevant. `--thorough` relaxes those scan settings,
but does not disable parser safety limits, image bounds or preview output caps.
It is not a request for an unrestricted database export.

Examples of retained limits:

| Format | Selected limits |
|---|---|
| `.4dm` | At most 256 KiB of input and 1,000 displayed lines, with truncation notices |
| `.4si`, `.4df`, `.4lbp`, `.4DForm` | 4 MiB input limits, plus format-specific complexity bounds |
| `.4DCatalog`, `.4qr` | 32 MiB input limits, plus format-specific complexity bounds |
| `.4st` | First 200 observed contiguous ranges in the output; no arbitrary whole-file size cutoff |
| `.4vp` | 16 MiB JSON, 100,000 JSON values, 20,000 saved cells; HTML shows up to 16 visible sheets, 200 visible rows and 40 visible columns per sheet |

Some limits reject the document; others return an explicitly partial or
truncated result. Read the notices and JSON status fields. The linked format
notes describe the detailed contracts.

For project-aware forms, catalogs and label/table-form references, preserve the
project's directory layout. Relative resources, catalog editor data, local
stylesheets, inheritance, static subforms and localization files can affect
the result. The CLI uses ordinary filesystem permissions and does not use the
Quick Look app's folder-authorization UI; macOS privacy permissions still apply.
Moving a form into an isolated folder
can therefore change its preview or produce missing-resource notices.

Reports can contain saved text, paths, metadata and embedded artwork.
Review generated JSON, HTML and screenshots before sharing them publicly.

## Errors and automation

Current exit-status behavior is important when scripting:

| Situation | Exit status and output |
|---|---|
| `--help` or `--content-types` | `0`; requested information on stdout |
| No file paths supplied | `2`; usage on stderr |
| Successful JSON analysis | `0`; JSON on stdout |
| At least one JSON input fails to open, parse or match an analyzer | `1`; error on stderr; other inputs are still attempted |
| Text or HTML analysis fails | An error report is written to stdout; the process currently still exits `0` |

Use `--json` to check analysis success in automation. Do not treat a zero exit
status from text/HTML mode as proof that a document was parsed successfully.
For multiple JSON inputs, successful models and stderr errors can both be
present in the same invocation.

An unrecognized extension, missing file, unsupported format version, malformed
document or exceeded safety limit produces an explicit error. The tool does
not silently convert it into another file format.

## Building from source

The release downloads are ready to run. To build a local CLI instead, use a
compatible Swift toolchain and, on macOS, the Xcode command-line tools:

```sh
git clone https://github.com/miyako/4d-ql.git
cd 4d-ql
swift build -c release --product fourdql
BIN_DIR="$(swift build -c release --show-bin-path)"
"$BIN_DIR/fourdql" --help
```

For a development invocation:

```sh
swift run fourdql --html "/path/to/Workbook.4vp" > workbook.html
```

Source builds are not the Developer ID-signed, notarized release artifact.
On Windows, use Swift with the Visual Studio C++ tools and Windows SDK; the
executable is `fourdql.exe`. See the [Windows handover](WINDOWS-HANDOVER.md).
Linux hosted builds use Swift 6.2.3 on Ubuntu 24.04; their rendering limitations
also apply when building from source.

## Hosted builds and releases

[CI](../.github/workflows/ci.yml) calls the reusable
[portable CLI workflow](../.github/workflows/cli-build.yml) on pull requests,
pushes to `main`, and manual dispatch. Independent hosted Windows and Linux
jobs run the Swift tests, build release executables, collect redistributable
runtime dependencies and upload distribution archives with 14-day retention.
Each archive is extracted into a directory containing spaces and exercised
from outside the checkout with Swift/toolchain environment paths removed.
The smoke check covers text, typed JSON and HTML for all 16 document families,
the `.data` alias, options and documented failure statuses.
Linux repeats the check in a clean Ubuntu container without Swift installed,
with fixture/package mounts read-only and networking disabled.

The [release workflow](../.github/workflows/release.yml) uses the same package
jobs for `vX.Y.Z` tags. It attaches their archives after the macOS job creates
the release, avoiding competing release-creation requests. A failed portable
job does not publish an untested archive. Windows/Linux builds do not need
Apple signing or notarization secrets.

For an existing release whose tag includes the workflows and packaging
scripts:

```sh
# All CLI packages, without replacing the Quick Look app:
gh workflow run release.yml -f tag=vX.Y.Z -f cli_only=true

# Windows/Linux packages only, without invoking macOS signing:
gh workflow run release.yml -f tag=vX.Y.Z -f portable_only=true
```

Both modes require the GitHub Release to exist. They replace only the requested
CLI assets, not the app downloads or release notes. The workflow builds the
specified tag, not the latest branch: it cannot retrofit new packaging scripts
or portability fixes into a tag predating them. Make a new patch release for
such source changes. Older tags retain their macOS-only full/`cli_only` rebuild
behavior; `portable_only` rejects them explicitly.

To reproduce a package locally after a release build:

```powershell
swift build -c release --product fourdql
./scripts/package-cli-windows.ps1 -Version X.Y.Z
```

```sh
swift build -c release --product fourdql
bash scripts/package-cli-linux.sh X.Y.Z
```

Both write to `dist/`. Run `python3 scripts/test-cli-package.py --archive
dist/ARCHIVE_NAME --scratch /path/to/scratch` (`python` on Windows) to exercise
the resulting archive. Keep the included runtime dependency lists and license
notices when redistributing it.

## Reproducing the screenshots

The gallery is generated from repository fixtures and small documentation
examples. The [capture manifest](images/cli/manifest.json) records the source
and whether each input is an existing fixture or a constructed example.
Screenshots demonstrate the renderer, not the authenticity of a synthetic
sample as a document saved by 4D.

On macOS with a graphical login, Swift, Python 3 and the repository checked out:

```sh
swift build --product fourdql
python3 scripts/make-cli-screenshots.py \
    --scratch "$HOME/Library/Caches/4d-ql/cli-screenshots"
```

The generator runs the CLI, checks that analysis succeeds and captures the
resulting HTML in WebKit. It does not need a licensed 4D installation.
The scratch directory holds generated HTML, the snapshot helper and validation
metadata; only the PNGs and source manifest belong in `docs/images/cli`.
Use `--only form` (or another manifest stem) to regenerate a single image.
